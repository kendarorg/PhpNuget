# Integrate simple-ui-framework (uifw) as the PhpNuget UI + auth layer

## Context

PhpNuget is a PHP NuGet server mid-rewrite: clean namespaced code under `src/` (PSR-4 `lib\…`,
composer autoload, `OminousFactory` DI, dual file/mysql DB backend, nuget OData protocol in
`lib/rest`), with the legacy app parked in `src.old/`. Still **unported** from `src.old`: the web
UI (Angular 1.x + server partials), login/session auth, setup/installer, download counting.

Rather than re-port the legacy Angular UI and hand-roll auth, we adopt
`/mnt/c/Data/Dev/simple-ui-framework/php` (uifw) — a complete vanilla-JS widget UI + bcrypt
auth/RBAC/audit/i18n stack — for **the human UI and its UI-facing data APIs only**. The
**nuget protocol** (v1/v2 OData feed, package upload/download, `lib/rest`) stays exactly as is.

Decisions taken with the user:
- **Everything on MySQL.** The integrated system runs on a single MySQL DB; the flat-file backend
  is no longer the deployment path (code/tests for it remain but unused).
- **Merge users.** uifw's `users` table becomes the single user store; nuget user fields
  (API key/token, admin flag→role) fold into it. The separate nuget `users` table goes away.
- **Vendor uifw into the repo**, build the nuget UI as the "app" on top (uifw_sample pattern).
- **This plan delivers: foundation + auth + ONE vertical slice** (the Packages list page).
  Remaining pages (package detail, profile/my-packages, upload UI, users admin) follow the same
  pattern in later passes.

## Architecture

Two PHP worlds coexist in one deployment, bridged at one seam:

| Concern | Stack | Location |
|---|---|---|
| Nuget OData protocol, upload/download | namespaced `lib\…` + composer | `src/api/v1`, `src/api/v2`, `src/lib/rest`, `src/upload` (unchanged) |
| Human UI + UI data APIs + auth | uifw (global classes, GlobalRegistry, PDO/MySQL) | **new `src/app/`** |
| Shared persistence | one MySQL DB | uifw tables + nuget `packages` table |

The seam: a uifw `BaseApis` subclass (`src/app/api/packages.php`) `require`s PhpNuget's
`vendor/autoload.php` and reads packages through `lib\nuget\NugetPackages` (mysql backend via
`OminousFactory`), returning them in uifw's `{items, labels, permissions}` envelope. uifw never
talks to `lib\nuget` except inside these bridge API files.

Web routing: UI mounts at `/app/` (its own `index.php` → `ui/login.html`/`dashboard.html`, APIs at
`/app/api/*`). The nuget protocol keeps the site root (`/`, `/api/v2`, …) via the existing
rewrite rules — no collision.

## Work items

### 1. Vendor uifw as the app skeleton
- Copy `simple-ui-framework/php/uifw_core/` → `src/app/`. This brings the framework (`lib/`,
  `utils/`, built-in `api/` login·users·roles·functionalities·translations·globalRegistry·
  maintenance, `models/`, `ui/` pages, `translations/`, `config/`, `setup/`, `index.php`,
  `config.inc`).
- Strip framework-irrelevant leftovers not needed by a nuget server (review `lib/utils/InvoiceParser`,
  report/xlsx pieces) — keep them if low-cost; they're harmless.

### 2. Bridge uifw config to the nuget DB + composer
- In `src/app/config.inc`, after the GlobalRegistry bootstrap, `require_once` PhpNuget's
  `src/vendor/autoload.php` so `lib\…` classes are usable inside bridge APIs.
- Point uifw `config/db_config.php` (`DB_HOST/DB_NAME/DB_USER/DB_PASS`) and PhpNuget's
  `src/conf/properties.json` (`dbType=mysql` + same MySQL creds) at the **same** database, so
  `OminousFactory`'s `MySqlDbStorage` and uifw's PDO hit one DB. Generated by setup (item 4).

### 3. Merge the user model (auth = nuget identity)
- Extend uifw `users` table with nuget columns: an **API key / token** column (replacing legacy
  `Token`), and confirm role↔admin mapping (`SuperAdmin`/`Admin` = nuget admin). Owned packages
  derive from the `packages` table's owner/UserId column, not a per-user list.
- Re-point **nuget upload** (`src/upload/index.php`, currently
  `new UserDb()->Query("Token eq '{…}'")` via `lib\nuget\NugetUsers`) to resolve the uploading
  user by API key against the merged `users` table. Simplest: a small bridge that reads the uifw
  `users` row by apiKey (PDO) and yields the user id; drop the dependency on the now-removed nuget
  `users` table.
- Retire legacy session auth: delete the `require __ROOT__/inc/logincontroller.php` cords from
  `src/index.php` and `src/api/users/index.php` (the new UI/login is uifw Auth). Old admin-gated
  `src/api/users/index.php` is superseded by uifw `UsersApi`.

### 4. Setup / schema (single MySQL DB)
- Extend uifw `src/app/setup/setup.sql` (+ seed) to also create the nuget **`packages`** table
  (schema from `src/lib/nuget/fields/mysql/` — `NugetPackageConverter` / `mysqlfunctions.sql`) and
  add the nuget columns on `users`; seed a **`packages` permission module** (e.g. `Admin: packages:CRUD`,
  authenticated users get read).
- One run of `src/app/setup/setup.php` provisions: uifw tables + SuperAdmin + nuget `packages`
  table, and writes both config files (uifw `config/config.php` and PhpNuget
  `src/conf/properties.json`) — extend the setup writer to emit the latter.

### 5. Vertical slice — Packages list page
- **API**: `src/app/api/packages.php` → `class PackagesApi extends BaseApis`.
  - Constructor: `auth->userMustBeLoggedIn()`, `permissions = auth->loadPermissions('packages')`.
  - `apiCallPostSearch()`: read uifw `SearchQuery` (`getJsonPostData('SearchQuery')`), translate
    its `searchTerms`/paging into a `lib\nuget` query string, call
    `OminousFactory::getObject('nugetpackages')->query(...)` (or `queryAndCount`), return
    `{items, labels, permissions}` (mirror `uifw_sample/api/accounts.php`).
  - Group-by-Id for the gallery view (legacy used `groupBy Id`).
- **Model**: prefer a thin bridge in the API over a uifw `BaseModel` (packages don't live in a uifw
  CRUD table) — `BaseModel` is for uifw-managed tables; here the data comes through `lib\nuget`.
- **Page**: `src/app/ui/packages.html` (includes `commons/head|header|menu`, `bootstrap({PAGE-TITLE:'packages', LOAD-PERMISSIONS:'packages', PAGE-MODULE:'./js/packages.js'})`) +
  `src/app/ui/js/packages.js` exporting `initPage(registry)` that builds a `Grid` posting to
  `/app/api/packages?action=search`.
- **Menu**: override the `globalRegistry` bootstrap API (register a nuget `BootstrapApi`, per
  `pages-menu-i18n.md`) to add the Packages entry, filtered by the `packages` permission.

## Critical files
- New: `src/app/**` (copied uifw_core), `src/app/api/packages.php`, `src/app/ui/packages.html`,
  `src/app/ui/js/packages.js`, nuget `globalRegistry`/bootstrap override, extended
  `src/app/setup/setup.sql`.
- Modified: `src/upload/index.php` (apiKey lookup), `src/index.php` & `src/api/users/index.php`
  (drop legacy `logincontroller`), `src/conf/properties.json` (mysql), uifw `config/db_config.php`.
- Reused as-is: `src/lib/nuget/NugetPackages.php`, `src/lib/db/mysql/*`, `src/lib/OminousFactory.php`,
  `uifw_sample/api/accounts.php` (template), uifw `lib/Auth_singleton.php`, `lib/BaseApis_base.php`.

## Out of scope (later passes, same pattern)
Package detail page, profile/my-packages, upload UI, users-admin page (uifw `users.html` mostly
works already), download counting (`NugetDownloads::incrementDownloads` is still a stub),
removing the dead flat-file DB code.

## Verification
1. Create an empty MySQL DB; run `src/app/setup/setup.php`, fill the form → confirm uifw tables +
   `packages` table created, SuperAdmin row present, both config files written.
2. Browse `/app/` → redirected to `ui/login.html`; log in as SuperAdmin → dashboard.
3. Open the Packages page → Grid loads packages from MySQL via the bridge API; search/paging work;
   `permissions` envelope hides actions for a read-only user (test with a non-admin role).
4. Regression: hit a nuget protocol endpoint (`/api/v2`, OData feed) and run an existing
   `tests/integration/ApiRootTest.php` to confirm the protocol side is untouched.
5. `nuget push` / upload with an API key resolves the user against the merged `users` table.
